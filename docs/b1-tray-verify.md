# B1 托盘常驻 — 交付说明与手动验证清单

2026-10-09 交付。自动化已覆盖的部分（全部通过）：

- 无头常驻内存 **167.6MB**（基线 ~400MB）；开窗 300.3MB；点 × 关窗后 **207.3MB**（renderer 86.5MB 随窗口销毁释放）
- 关窗后：进程存活、端口仍监听、`GET /` 仍 200（后台签到/旅行/保活与网关不中断）
- 功能回归：`GET /` 200；hy3 带 tools 的 `POST /v1/messages` 返回 `stop_reason=tool_use`、工具参数正确
- exe/asar 内容核对：托盘代码与 `build/icon.ico` 确认打进包（grep + asar 头解析）

需要人工点一遍的（系统托盘无法自动化，共 3 次点击）：

1. 启动 wb-desktop-portable.exe → 通知区出现图标，悬停提示「WorkBuddy 账号助手（后台运行中）」
2. 点主窗口 × 关闭 → **窗口消失但程序仍在托盘运行**（图标还在；`netstat -ano | findstr 3081` 仍在监听）
3. 右键托盘图标 → 「打开主界面」→ 窗口重新出现（约 1 秒，页面会重新加载）；双击图标等效
4. 右键托盘图标 → 「退出」→ 托盘图标消失、进程全部结束（任务管理器无 WorkBuddy 进程）→ 这才是真正的退出

## 重要行为变化（需知悉）

- **点窗口 × 不再退出程序**：程序缩到托盘继续后台运行；从托盘菜单「退出」才是真退出
- 关窗即销毁窗口：下次打开是全新窗口（UI 状态重载，后台数据不受影响）
- 内存下限说明：Chromium 132 的 network/gpu 辅助进程无法归零（`disable-features=NetworkService`、`--network-service-in-process` 均实测无效），常驻约 170MB 是当前架构下限

## 测试/无头模式

`WB_PORT=3099 WB_NO_OPEN=1` 环境变量可起一个不弹窗、只跑后台的实例（托盘照常），供测试与自启场景。
