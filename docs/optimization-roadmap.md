# wb-desktop 待优化功能项（对照 workbuddy-switch 分析）

分析基准：workbuddy-switch（wbs）@ 当前 master，wb-switch-core 37 个模块 + wb-switch-server（axum WebUI API）+ Tauri 桌面壳。
结论先行：**wbs 没有"模型转发代理"**（全仓库无 chat/completions 转发代码）——它的"模型方案"是三层可观测性（限额 hook → 限额台账 → 官方用量对账）。wb-desktop 的网关（转发 + 多账号 + 计量）是 wbs 没有的；反过来 wbs 有六块能力 wb-desktop 尚未覆盖。

## A. 模型可观测（wbs 的"模型代理方案"，建议优先移植）

| # | 项 | wbs 参考 | wb-desktop 现状 | 价值 |
|---|---|---|---|---|
| A1 | **模型限额台账** | `limits.rs`（46 个测试）：扫描客户端日志，按 (账号, 模型) 聚合 429 限流事件、解析官方恢复时刻（"将在 2026-09-17 17:59:27 UTC+8"），去重/归因/过期剔除 | 无。ZCode agent 连续调用时被限流只能盲等 | 直接回答"哪个模型被限了、几点恢复"；网关可据此**自动避开受限模型/账号**（与网关的天然结合点） |
| A2 | **限额 hook 安装器** | `rate_limit_hook.rs`：把 Stop+FinalStop 事件注册进 `~/.codebuddy`、`~/.workbuddy`、`~/.workbuddy-ai` 三处 settings.json，hook 脚本追加 jsonl 事件供后端消费；幂等/写前备份/逐字节还原 | 无 | A1 的数据源；wb-desktop 已有备份/原子写基础设施，移植成本低 |
| A3 | **官方请求级用量对账** | `official_usage.rs`：`get-user-request-usage` 31 天分页扫描（3000/页、安全上限 100 轮、去重边界合并），按模型/客户端归因每一条请求的积分；缓存脱敏 | 无——网关台账只覆盖走网关的流量，App 内消耗是黑盒 | 完整对账：官方口径 vs 网关台账差值 = App 内消耗；验证"积分与 App 内一致"的长期手段 |
| A4 | **用量统计投影** | `credit_usage.rs`（12 测试）+ `token_stats.rs`：快照差分出每日用量曲线、7 天/月窗口、签到关联、90 天保留；统计事件环 200 条 | 只有余额与实时台账（200 条环形，重启保留但无趋势） | "这个账号每天烧多少积分"的趋势视图；积分消耗与到期分析依据 |

## B. 账号管理补齐（wbs 已有、wb-desktop 缺失）

| # | 项 | wbs 参考 | 说明 |
|---|---|---|---|
| B1 | **后台常驻 + 系统托盘** | `tray.rs`、Tauri 常驻 | ✅ **已交付**（2026-10-09，见 `docs/b1-tray-verify.md`）：关窗缩托盘不退出，后台循环与网关持续运行 |
| B2 | 账号备注/别名 | `update-account-display` API | 账号库现在只有 email/nickname；给账号起备注（"主力""备用-张三"）便于网关选择与账号识别 |
| B3 | 应用内通知中心 | `notifications.rs`：100 条环形、去重窗口、截断规则 | 签到失败等事件现在只进日志；通知中心 + 系统通知才不漏事件 |
| B4 | 版本检查/自更新 | `update.rs` + `update_service.rs` | portable exe 分发无自动更新；至少做版本检查提示 |

## C. 大工程（wbs 核心能力，按需立项）

| # | 项 | wbs 参考 | 说明 |
|---|---|---|---|
| C1 | **会话管理**（复制/同步/跨档） | `session.rs`（7244 行，83 测试）+ `session_backup.rs` + `session_link.rs` | 切号带走会话历史。此前按需求明确不做；若要做建议独立立项（工作量 ≈ 重做半个 wbs） |
| C2 | IDE 凭据注入 | `codebuddy_ide*.rs`、`vscode_ext.rs`、`vscode_cn_inject.rs`、`jetbrains.rs` | 目前只覆盖桌面端认证文件 + CLI env；IDE（CodeBuddy 国际/国内、VS Code 插件、JetBrains）切号不在范围内 |
| C3 | Linux 凭据 keyring | `linux_keyring.rs` | 仅 Linux，优先级低 |

## D. 网关自身的待优化项（本项目原生）

| # | 项 | 说明 |
|---|---|---|
| D1 | **限额感知的账号/模型切换** | A1 落地后：上游 429/受限时按台账自动换账号或换模型，而不是把限流错误透传给客户端 |
| D2 | 11128 重试的可见性 | 自动重发成功时在台账记一条 "11128 已自动重发"，用户可知道发生过拦截 |
| D3 | 请求耗时维度 | 台账补 latencyMs；汇总里出 P50/P95 |
| D4 | 汇总统计自动刷新 | 用量面板可加 30s 轮询开关（当前手动点「刷新统计」） |
| D5 | 失败请求的错误分类 | 把上游错误码归类（风控/限流/鉴权/网络），为 D1 的策略提供依据 |
